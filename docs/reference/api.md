# C++ API

The simulator is built on two libraries that can be reused by other programs: `core`, the
simulation engine and every encoder, with no Qt dependency, and `io`, the profiles,
transports and runner built on Qt's non-GUI modules. The
[architecture overview](../explanation/architecture.md) explains how they fit together.

**[Open the C++ API reference](../api/index.html)**

The reference is generated by [Doxygen](https://www.doxygen.nl/) from the public headers
under `src/core/include/` and `src/io/include/` every time the documentation is built, so it
always matches the source of this documentation version.

| Library | CMake target | Main entry points |
| --- | --- | --- |
| `core` | `nmeasim::core` | `simulation::Simulation`, `simulation::DeltaSource`, `simulation::TrackSource`, `simulation::ReplaySource`, `nmea0183::SentenceRegistry`, `ais`, `signalk`, `viewsync` |
| `io` | `nmeasim::io` | `Profile`, `SimulationRunner`, `Transport` and its implementations |

The libraries are linked statically into the desktop application and the command-line
tool. Their interfaces follow [Semantic Versioning](https://semver.org/) from 1.0 onwards
only in so far as the applications do; programs that embed them should pin a release.

## Building the reference locally

```bash
doxygen --version                      # 1.18 or later; CI uses 1.18.0
NMEASIM_VERSION=dev doxygen tools/doxygen/Doxyfile
xdg-open build/doxygen/api/index.html  # open on macOS, start on Windows
```

`mkdocs build` and `mkdocs serve` run the same command through the hook in
`tools/doxygen/mkdocs_hook.py` and publish the output under `api/`. Doxygen treats warnings
as errors: every public class, function and member must carry a `///` comment.
